## Problem Statement

Threads에서 콘텐츠를 만들 때, 어떤 게시물이 왜 잘 되는지 체계적으로 분석할 방법이 없다. ViewStats가 YouTube에서 아웃라이어 영상을 찾아주듯이, Threads에서도 특정 계정의 게시물 중 비정상적으로 잘 된 것을 찾고, 그 이유를 분석하고, 내 글쓰기에 적용할 수 있는 인사이트를 제공하는 도구가 필요하다.

## What Makes This Cool

ViewStats는 아웃라이어를 **찾아주기만** 한다. Santiago는 찾고 + **왜 잘 됐는지 LLM으로 분석**까지 해준다. 이게 ViewStats에 없는 기능이고, LLM 시대에 가능해진 것.

추가로, 여러 계정에서 저장한 게시물들을 컬렉션에 모으면, **계정을 넘어서는 공통 패턴**을 AI가 발견해준다. 개별 분석 + 교차 패턴 분석이 Santiago만의 차별점.

## ViewStats 레퍼런스 모델

| ViewStats 기능 | Santiago 대응 |
|---------------|--------------|
| 아웃라이어 점수 (최근 10개 평균 대비 배수) | 동일 방식 적용 (최근 N개 평균 engagement 대비) |
| 필터/정렬 (조회수, 채널 크기, 점수) | 필터 슬라이더 (배수 임계값 조절) |
| Search Similar Outliers | V2에서 키워드/니치 기반 크로스 계정 검색 |
| Collections (북마크) | 단일 컬렉션에 게시물 북마크 + 패턴 분석 |
| 썸네일 + 제목 표시 | 게시물 텍스트 + engagement 지표 표시 |
| (없음) | **AI 분석 (6차원 프레임워크) — Santiago만의 차별점** |
| (없음) | **교차 패턴 분석 — 컬렉션 내 게시물들의 공통 패턴 발견** |

## Core Flow

```
1. 계정 입력 (@username)
2. Apify로 전체 게시물 수집 (1000개+ 시 최근 200개 제한)
3. 아웃라이어 점수 계산 (최근 10개 평균 engagement 대비 배수)
4. 기본 3x 이상 → 아웃라이어로 표시 (슬라이더로 2x~10x 조절)
5. 개별 게시물 "분석하기" 클릭 → LLM이 6차원 분석
6. 마음에 드는 게시물을 컬렉션에 북마크
7. 컬렉션에서 "패턴 분석하기" → 저장된 게시물들의 공통 패턴 추출
```

## 아웃라이어 점수 계산

ViewStats 방식을 Threads에 적용:

- **기준**: 해당 게시물의 total engagement / 최근 10개 게시물의 평균 engagement
- **total engagement** = 좋아요 + 리포스트 + 답글 (가중치 없이 합산, V1)
- **임계값**: 기본 3x (사용자가 슬라이더로 조절 가능)
- **개수 고정 아님**: 3x 이상이면 2개든 20개든 모두 표시

```
예시: @garyvee (324 posts, avg engagement 1,247)
→ 3x 이상: 18개 아웃라이어
→ 5x 이상: 7개
→ 10x 이상: 2개
```

## 컬렉션 기능

- **단일 컬렉션** — 여러 컬렉션이 아니라 하나의 "내 컬렉션"에 북마크
- 아웃라이어 결과에서 **하트 아이콘**으로 저장
- 계정별 필터 칩으로 컬렉션 내 필터링 (전체 / @garyvee / @sfreedman / ...)
- **"패턴 분석하기" 버튼** → LLM이 저장된 게시물들의 공통 패턴 추출
- 같은 패턴이 여러 계정에서 발견되면 → 증거가 쌓이는 구조 (중복이 아닌 강화)

## 분석 프레임워크 (리서치 기반)

### 개별 게시물 분석: 6차원 (LLM 텍스트 분석)

리서치 결과, Threads 알고리즘은 인게이지먼트 속도(40%) + 완독률(25%) + 대화 품질(20%)을 가장 중시한다. 이에 맞춰 분석 차원을 설계:

| # | 차원 | 가중치 | 평가 내용 |
|---|------|--------|----------|
| 1 | **훅 (Hook)** | 15% | 첫 줄의 호기심/충격/공감 유발력. 정보 격차, 구체적 숫자, 2인칭("you") 사용 |
| 2 | **감정 각성 (Emotional Arousal)** | 15% | 고각성 감정(awe, anger, curiosity) 유발 여부. 저각성(sadness)은 공유 억제 |
| 3 | **본문 구조 (Structure)** | 10% | Hook→Value→CTA 구조, 줄바꿈, 리스트/넘버링, 시각적 공백 |
| 4 | **CTA** | 12% | reply 유도 강도, engagement bait 여부 (Meta 페널티 감지), 자연스러움 |
| 5 | **대화 유발력 (Conversation Catalyst)** | 12% | 양면적 주제, 경험 공유 유도, reply 가능성 |
| 6 | **공유 동기 (STEPPS)** | 8% | Social Currency, Practical Value, Stories — 리포스트 동기 분석 |

### 자동 메타데이터 분석 (Apify 데이터)

| 차원 | 데이터 소스 | 분석 방법 |
|------|-----------|----------|
| **미디어 유형** | Apify | 텍스트/이미지/캐러셀/동영상 분류 (사진 +60%, 링크 -37%) |
| **길이** | 글자 수 자동 계산 | 최적 구간: 1-3문장(50-150자) 또는 구조화된 300-500자 |
| **타이밍** | Apify (게시 시간) | 최적 시간대 대비 평가 (수요일 오전 7시 = 전체 1위) |
| **타래 구조** | Apify | 단일 포스트 vs 타래, 타래 길이 |

### 훅 유형 분류 (고성과 패턴)

분석 시 아래 훅 유형 중 어디에 해당하는지 태깅:

1. **호기심 훅**: "What nobody tells you about [niche]..."
2. **숫자 훅**: "3 simple steps to [achieve result]"
3. **충격 훅**: "The biggest mistake I made on Threads"
4. **공감 훅**: "Struggling to grow your audience? You're not alone."
5. **예언 훅**: "By 2035, [everyday thing] won't exist..."
6. **경험 축약 훅**: "I've posted 500+ times. Here are 7 types that always go viral"

### 컬렉션 패턴 분석 (교차 분석)

컬렉션의 "패턴 분석하기" 실행 시:

1. 저장된 모든 게시물의 개별 분석 결과를 종합
2. 공통 패턴을 **패턴 카드**로 클러스터링:
   ```
   패턴: Curiosity Gap Hook
   발견: 4개 계정에서 12회 사용
   예시:
     - @garyvee: "Here's what nobody tells you..."
     - @sfreedman: "You're making this mistake..."
     - @chrispjones: "Everyone says X. They're wrong..."
   평균 배수: 8.3x
   ```
3. 패턴별 평균 배수, 빈도, 대표 예시 제공
4. **실행 가이드**: 각 패턴을 내 글에 적용하는 방법 제안

### 리서치 출처

- Berger & Milkman (2012) — 고각성 감정이 공유를 촉진
- Berger STEPPS 프레임워크 (Contagious, 2013) — 6가지 공유 원리
- Buffer 250만 포스트 분석 — 최적 포스팅 시간, 미디어별 성과
- MomentumHive — Threads 알고리즘 구조 (속도 40%, 완독률 25%, 대화 20%)
- Adam Mosseri 발언 — "Reply가 post만큼 가치 있다"

## Constraints

- **데이터 소스:** Threads 공식 API 없음. Apify Actor를 통한 스크래핑.
- **분석 엔진:** LLM(Claude) 기반. 정량 지표로 아웃라이어 선정 후, 정성 분석은 LLM.
- **사용자:** 본인 1명. 스레드 커뮤니티에 공유할 수 있도록 배포된 URL 필요.
- **기술 스택:** Next.js + Supabase + Vercel (CLAUDE.md 컨벤션 준수)
- **비용:** Apify 크레딧 + Claude API 호출 비용 발생. 개인 사용이므로 최적화보다 기능 우선.
- **스캔 범위:** 계정당 전체 게시물 수집. 1000개 초과 시 최근 200개로 제한.
- **UI 언어:** 한국어

## Premises

1. Apify를 통해 Threads 게시물의 engagement 지표(좋아요, 리포스트, 답글 수)를 수집할 수 있다.
2. "아웃라이어"는 ViewStats 방식 — 최근 10개 게시물 평균 대비 배수(기본 3x+)로 정의한다.
3. LLM이 게시물 텍스트를 분석하여 6개 차원(훅, 감정, 구조, CTA, 대화유발, 공유동기)의 패턴을 식별하고 실행 가능한 인사이트를 제공할 수 있다.
4. 웹 UI가 필요하다 — 결과 탐색, 분석 비교, 컬렉션 관리에 시각적 인터페이스가 효과적.
5. 컬렉션은 단일 컬렉션으로 충분하다 — 여러 컬렉션은 관리 오버헤드만 늘린다.

## Approaches Considered

### Approach A: "One-Shot Analyzer"
- 웹 폼 → Apify 스크래핑 → 아웃라이어 계산 → Claude 분석 → 결과 표시
- DB 없음, 인증 없음. 매번 새로 스크래핑.
- Effort: S / Risk: Low
- Pros: 즉시 사용 가능, 코드 최소
- Cons: 결과 휘발, 컬렉션 축적 불가, 반복 비용

### Approach B: "Personal Dashboard" (선택됨)
- Next.js + Supabase로 분석 결과와 컬렉션 영구 저장
- 계정별 히스토리, 컬렉션, 패턴 분석 캐시 활용
- Vercel 배포로 공유 가능한 URL
- Effort: M / Risk: Low-Med
- Pros: 데이터 축적, 재분석 즉시, 컬렉션에서 패턴 발견
- Cons: 초기 셋업 (Supabase + 스키마 + RLS)

## Recommended Approach

**Approach B: Personal Dashboard**

## 정보 위계 (Information Architecture)

### 네비게이션 모델
```
┌────────────────────────────────────────────────┐
│ Santiago (← 홈)              내 컬렉션 (23)    │
└────────────────────────────────────────────────┘
```
- 최소 상단 바: Santiago 로고(홈 링크) + 컬렉션 링크(아이템 수 배지)
- 결과/분석 화면: ← 뒤로가기 텍스트 링크 추가 (브라우저 뒤로가기 의존하지 않음)
- 로그인 화면: 네비게이션 없음 (인증 전)

### 화면 흐름
```
[로그인] → [홈] ──→ [결과 /results/:username] ──→ [분석 /analysis/:postId]
                │                                       │
                └──→ [컬렉션 /collection] ←── 하트로 저장 ─┘
```

### 1. 홈 (/)
- **1순위:** 계정 입력 (Input with Button, DESIGN.md) — 화면 중앙, 유일한 인터랙션 요소
- **2순위:** Santiago 브랜드 (Satoshi 900) + "Threads 계정의 아웃라이어를 찾아드립니다" 안내
- **이력 카드 없음** — 홈은 순수 입력 터미널. 이전 결과는 같은 username 입력 시 결과 페이지에서 캐시로 즉시 표시. 컬렉션이 "돌아가는 곳" 역할.

### 2. 아웃라이어 결과 (/results/[username])
- **1순위:** 슬라이더 필터 (outlier-slider) — 화면 상단, 현재 임계값 즉시 파악
- **2순위:** 아웃라이어 리스트 (Outlier Item 4컬럼, DESIGN.md) — 배수 내림차순
- **3순위:** 계정 요약 헤더 (@username, 총 게시물 수, 아웃라이어 수, 기준 배수)

### 3. 분석 상세 (/analysis/[postId])
- **레이아웃:** 2컬럼 (eng plan 명시)
- **좌측 (원문 패널, ~40%):** 게시물 전문 + engagement 지표 (❤ 🔄 💬) + 컬렉션 저장 버튼
- **우측 (분석 패널, ~60%):** 6차원 정성 분석 (Dimension Card, DESIGN.md — 점수/프로그레스 바 없음, 텍스트만)
- **1순위:** 분석 텍스트 (우측, 더 넓음 — 사용자가 이 화면에 온 이유)
- **2순위:** 원문 (좌측, 분석의 맥락 제공)
- **3순위:** 액션 (컬렉션 저장)

### 4. 컬렉션 (/collection)
- **1순위:** 필터 칩 (Filter Chips, DESIGN.md) — 계정별 빠른 필터링
- **2순위:** 컬렉션 아이템 리스트 — Outlier Item 변형 (계정명 추가, 삭제 버튼)
- **3순위:** 패턴 분석 (버튼 + 결과) — 아이템이 충분할 때만 활성화
- **패턴 분석 결과:** 컬렉션 리스트 아래에 패턴 카드 섹션으로 표시

### 5. 로그인 (/login)
- 중앙 정렬: Santiago 로고 + 비밀번호 입력 + 로그인 버튼
- 미니멀, 단일 목적

### 스크래핑 대기 경험 (~2분)

- 2분 이상 대기 시: "예상보다 오래 걸리고 있습니다. 조금만 더 기다려 주세요." 안내

## AI Slop 방지 (Anti-Generic Design)

Santiago가 "또 다른 AI 생성 SaaS"처럼 보이지 않기 위한 구체적 차별화:

### 홈 화면
- 이력 카드 없음 → 순수 입력 터미널. 미니멀의 극치.
- Santiago 로고(Satoshi 900) + 한 줄 안내 + Input with Button만.
- 차별점: 대부분의 분석 도구가 대시보드+차트로 시작하지만, Santiago는 **빈 캔버스에 검색창 하나**. Google 검색처럼 "시작점"이 명확.

### 아웃라이어 리스트
- 4컬럼 그리드(DESIGN.md Outlier Item)가 이미 차별화됨: 배수를 amber JetBrains Mono 대형 숫자로 → 숫자 자체가 디자인 요소.
- "card grid" 아님 — 테이블에 가까운 밀도 높은 리스트. 카드 그림자/rounded corners 남발 금지.

### 패턴 카드 (컬렉션)
- 일반 "feature card with icon" 금지.
- 차별점: `avgOutlierScore`를 amber 배수 배지로 크게 표시 + `evidence` 게시물 스니펫을 인라인 블록인용으로 + 발견 계정 아바타를 겹쳐서 "여러 계정에서 확인" 시각화.
- 패턴 카드 = 증거 기반 인사이트 카드 (주장이 아니라 데이터 증거가 보임).

### 전반적 톤
- 그림자 최소화 (dark mode에서 그림자 = AI slop 1번 신호).
- border-color로 레이어 구분 (stone-700).
- 아이콘 남발 금지 — 텍스트와 숫자가 정보 전달.

### 네비게이션 (모바일)
- 상단 바 유지 (Santiago 로고 + 컬렉션 링크) — 2개 링크이므로 햄버거 불필요
- 터치 타겟 44px 확보

### 접근성 요구사항
- **색상 대비:** WCAG AA (4.5:1 본문, 3:1 대형 텍스트). amber-500 on stone-950 = 검증 필요
- **키보드 내비게이션:**
  - Tab으로 모든 인터랙티브 요소 접근 (입력, 슬라이더, 하트, 분석하기 버튼, 필터 칩)
  - 슬라이더: 화살표 키로 값 조절
  - Enter로 카드 클릭 (분석 상세로 이동)
- **터치 타겟:** 최소 44x44px (하트 버튼, 필터 칩, 네비게이션 링크)
- **ARIA:**
  - 슬라이더: `role="slider"` + `aria-valuemin/max/now` + `aria-label="아웃라이어 배수 필터"`
  - 하트 토글: `aria-pressed` + `aria-label="컬렉션에 저장/제거"`
  - 스트리밍 분석: `aria-live="polite"` (새 차원 도착 시 스크린 리더 알림)
  - 스크래핑 진행: `aria-live="assertive"` (상태 변경 알림)
- **스크린 리더:** 아웃라이어 배수를 "12.3배" 형태로 읽힘 확보

## What I noticed about how you think

- "분석만으로도 실행 가이드로 쓸 수 있을 것 같아"라고 했을 때 — 도구를 만드는 게 목적이 아니라, 도구가 만들어내는 결과물의 실용성을 먼저 생각하고 있었다. 분석과 실행 사이의 거리를 최소화하려는 사고방식.

- "A인플루언서도 curiosity hook을 썼어, B도 썼어 — 그러면 똑같은게 두개 아냐?"라는 질문 — 단순히 기능을 받아들이는 게 아니라 실제 사용 시나리오를 시뮬레이션하면서 설계 결함을 잡아냈다.
- "패턴 분석 전문으로 하는 에이전트가 있어야겠구만? 훅, 이미지활용, 타래 이런식으로 나눌 것 같은데"라고 한 것 — 바로 구현 구조를 떠올렸다. 분석의 축을 직관적으로 분류하고, 그게 전문 에이전트(프롬프트)로 나뉘어야 한다는 아키텍처 감각.

# Code Convention: Santiago

Generated by /plan-eng-review on 2026-03-27

## Naming

- **Files**: kebab-case (`post-card.tsx`, `outlier.ts`)
- **Components**: PascalCase (`PostCard`, `OutlierSlider`)
- **Functions/variables**: camelCase (`calculateOutlierScore`, `postCount`)
- **Constants**: UPPER_SNAKE_CASE (`SITE_PASSWORD`, `DEFAULT_THRESHOLD`)
- **Types/Interfaces**: PascalCase (`ApifyPost`, `PatternCard`)
- **DB columns**: snake_case (`total_engagement`, `outlier_score`)

## Directory Structure

- `src/app/` — Next.js App Router pages and API routes
- `src/lib/` — Business logic, clients, utilities
- `src/components/` — Reusable React components
- `src/middleware.ts` — Auth middleware
- `tests/unit/` — Unit tests (pure function, schema)
- `tests/integration/` — Integration tests (API routes, server actions)
- `tests/e2e/` — E2E tests (browser flow)

## Import Order

1. React / Next.js
2. External packages (`@google-cloud/vertexai`, `zod`, etc.)
3. Internal lib (`@/lib/...`)
4. Internal components (`@/components/...`)
5. Types (if separate)

## Patterns

- **Server Components by default.** `'use client'` only for interactivity.
- **Server Actions for mutations.** API Route Handlers only for webhooks and streaming.
- **Zod at boundaries.** Validate Apify responses, webhook payloads, user input.
- **`{ data, error }` pattern** for Server Actions. Never throw to client.
- **Streaming for LLM responses.** Use Route Handlers with `ReadableStream`.
- **Server-side polling** for scraping status (security: anon key isolation without RLS).

## Error Handling

- Never swallow errors. No empty `catch {}`.
- Server-side: log full error. Client-side: show safe message.
- Apify failures: show user-friendly error + retry button.
- LLM failures mid-stream: show partial result + error message.

## Testing

- **Vitest** for unit and integration tests.
- Pure functions (outlier calc, prompt builder): unit test with edge cases.
- API routes: integration test with mocked external APIs (Apify, Vertex AI).
- Auth middleware: integration test.
- E2E: browse-based full flow test.

## Commit Messages

- Imperative mood, max 72 chars.
- Explain why, not what.
- Examples: "Add outlier calculation with edge case handling", "Fix division by zero when account has no engagement"
